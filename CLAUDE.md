# CLAUDE.md

Notes for working on this repo (openMenu virtual-folder bundle, "NewOpenMenu" BIOS-style menu). Work happens on
the `dev` branch; `main` is the release line. Commit and push to `dev` when a change is finished.

## Layout
- `openMenu/src/bios_engine/` portable engine (Ninja models, script VM, scene, game list `bios_list.c`, pages, CD player).
- `openMenu/src/bios_rom/` reads the BIOS ROM dump. `openMenu/src/openmenu/src/` the app (`ui_bios.c` screens, `gfx.c` PVR backend).
- Vision: `openMenu/PROJECT_BRIEF.md` (the owner's consolidated brief: ideas and roadmap, not a statement of what exists). `ROADMAP.md` checks it against the code.
- Docs: `openMenu/NEWMENU.md` (design, per screen), `ROADMAP.md` (project brief vs code), `TEST_CHECKLIST.md` (hardware results, the user's notes: do not overwrite their measurements).

## Preview without hardware
`bios_preview` is not in CMake; build by hand (needs `dc_boot.bin`, MD5 e10c53c2f8b90bab96ead2d368858623, from the user):
```
cd openMenu/src
gcc -O2 -o <out>/bios_preview bios_engine/tools/bios_preview.c bios_engine/src/*.c bios_rom/src/*.c -Ibios_engine/include -Ibios_rom/include -lm
<out>/bios_preview dc_boot.bin list.ppm 60 <selected row> -3     # game list; BLIST_SLOTS=n, BLIST_DISC=n
```
Engine test: same gcc line with `bios_engine/test/bios_engine_test.c`, run `./t dc_boot.bin`. The preview draws text as outline boxes and
has no right panel; real text/art only on the PVR path (hardware).

## Game list (current state, see NEWMENU.md "Game browser")
- One box, fixed height 73.5-350.5 px, 7 lines (`UIL_VISIBLE`, engine max 13). Corners keep the single-row radius (y-growth in `bios_scene`).
- Disc and lit pill only on the selected row. Multi-disc number = 3D digit models at the CD's bottom right (`disc_number`).
- Favorites: `favorites.c/.h` (1.7.1 has none; own file, not OPENMENU.SYS: SD `FAVORITES.DAT` + memory card `OPENMENU.FAV`). Host-tested logic (pack/unpack, VMS wrap, crc); the card/SD I/O and UI are not compiled or run.
- Bottom row: Recent, Favorites (popup), Folders (top of tree), Sort (cycles A-Z / Year / SD order, `sf_sort`), Group (placeholder). Code in `ui_bios.c` (`button_text`, `cycle_sort`), order in `gd_list.c` `folder_cmp`. The app side cannot be compiled in the cloud session (no KOS; gnu.org is blocked); the owner compiles and tests on their side. Code for it is checked only with stub harnesses, so expect compile fixes after changes there.
- Serial VMU: `serial_vmu.c/.h` (restore before launch, backup at start; ported from main's `ui_menu_credits.c`, same SD layout; single image, no Slots). State machine host-tested with a fake VMU and SD folder (build with `-DSVMU_HOST_TEST -DSVMU_SD=... -DSVMU_EMPTY_VMU=...` and stub headers); the popup in `ui_bios.c` (`start_game`, `svmu_tick`) is not compiled.
- Online ("never connects", modem/serial/W5500 all tried): not diagnosed. Compared with main (`git diff origin/main HEAD -- openMenu/src/openmenu/src/backend/dcnow_net.c`): the engine is main's plus a serial-cable path that probes the serial port before the modem dial. Changes so far (untested): Auto-Connect starts after gfx/sound init, adapters connect on opening Internet, failure reason/advice shown. W5500 is in no engine. Needs the failure text from the owner.
- Internet screen (`ui_internet.c`): pages Online / Play / Events / News / Settings on the five CD buttons; syntax-checked on the host (`gcc -fsyntax-only` with a stub `arch/timer.h`, include paths of openmenu_shared/settings/bios_engine/bios_rom and external/crayon_savefile), not run.
- Main menu top bar: `update_clock` in `ui_bios.c` draws the clock (`clock_header_text` in `clock_math.c`, host-tested with `test/clock_test.c`) and, in the row above it in the same font, a connection lamp and "DCNow! n DCNet n" (`online_header_get`, `online.c`). Letters/AM/PM glyphs are generated by `tools/gen_clock_letters.py` into `bios_engine/src/bios_clock_letters.inc` (the ROM font has digits only). Clock format = `sf_clock` 0..4 (3 and 4 are this branch's .beat modes); .beat uses the Online time sync zone. Rendered on the host with the real engine code; the app side is not compiled.
- Header logo follows the online mode: `gfx_set_logo_mode` / `gfx_logo_badge` in `gfx.c` (not with a custom LOGO.PVR), `NOW.PVR` / `DCNET.PVR` (white letters, tinted at draw time, no BIOS artwork inside) are loaded from `/cd` by `gfx_load_logo_texts`; made by `openMenu/tools/gen_logo_text.py` (hand-drawn outlines in the style of the Dreamcast typeface, no font data; that typeface is personal-use only and must not be copied, it was only a visual guide) into the Card Manager's `tools/openMenu/menu_data`. DCNET mode crops the ROM logo to its swirl at run time (nothing of it is stored in the repo). PVR textures must have power-of-two sizes (64x32 and 128x32 here), mode chosen every frame by `update_logo_mode` from `online_header_get` (0 normal, 1 Now!, 2 DCNET, 3 connecting = swirl turns) (`network` from `dreampi_link_network()`). Composition checked on the host with the real ROM logo; the gfx code is not compiled. Header logo screen rectangle (measured on the preview): x 27..165, y 28..61.
- `BVM_MAX_OBJECTS` is 128 (13 rows need it).
